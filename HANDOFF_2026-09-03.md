## Left undone on purpose (do these first if they fit)

1. **The manual two-deploy test on the live site** (Path 1 verification line).
   Needs a real deploy. After #165 is live: open aspermylessonplan.com, wait
   about a minute, confirm the app bar reads "Offline: all 86 tools ready";
   then on the *next* deploy confirm the "A new version is ready" bar appears
   and Reload gets the new version. Record the result under Path 1 in
   `UPGRADE_PATHS.md`. Fifteen minutes; no code unless it fails.
2. **The accessibility baseline.** `Tools/a11y-sweep/allowlist.json` holds 91
   page-rule allowances on 59 pages, recorded on 2026-09-03 by the sweep's
   `--baseline` mode. They are real violations, not noise: 41 pages with an
   unlabeled `<select>`, 23 with an unlabeled input, 21 with muted-text
   contrast below 4.5:1, 5 title-only labels, 1 `aria-required-children`. The
   `select-name` and `label` classes are one `aria-label` (or a `<label for>`)
   each and would make a clean mechanical round — Sonnet-grade work, ~64
   pages. Contrast needs a palette decision per tool (or one decision in
   `_shared/theme.css` if Path 5 P1 lands first). The rule: fix, then delete
   the line; the suite goes red if the line outlives the bug. Never add a
   line for a new tool.
3. **The shell tier could lose 1.3 MB.** `SHELL_URLS` includes the vendored
   jsPDF and SheetJS because the plan said "vendor in the shell", but none of
   the ten shell tools use either. Moving those two to the deferred tier
   makes the install ~2.3 MB instead of ~3.6. One-line change plus a
   `CACHE_VERSION` bump; do it only with the two-deploy test above, so the
   readout is confirmed working first.
4. **An OS share sheet was never exercised.** The `share_target` contract
   (manifest POST → `sw.js` 303 → Class Roster Hub import dialog) is covered by
   two suites, but no one has shared a CSV from a phone into the installed
   app. If someone has an Android device or Chromebook with the toolkit
   installed, try it and note the outcome in Path 1 P4.

## What tripped this session up (so it does not trip the next one)

- **The web sandbox's Chromium.** `/opt/pw-browsers/chromium` exists but is
  build 1194; the pinned Playwright wants 1234, and
  `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD` turns `npx playwright install` into a
  no-op that prints success. Every browser suite here ran with
  `PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium`. Set it once at the top
  of the session. CI uses the right browser, and CLAUDE.md is right that CI
  is the authority.
- **Suite ports collide, and that is fine sequentially.** Many suites share
  a `PORT`; `run-suites.mjs` runs them one at a time. Never run two suites at
  once (CLAUDE.md says so; this session nearly did while a background
  `npm test` was running). New suites this round took 8401–8404; the 84xx
  range was empty.
- **`check-entities` is a floor by design.** Its first two drafts reported 618
  and then 176 findings, almost all data strings later rendered through
  `innerHTML`. What shipped reports only a string whose statement has a
  visible text sink and prints an advisory count (325) of strings it cannot
  classify. If it reports something, it is real. If you suspect a literal
  `&rsquo;` on a page it did not report, the sink is indirect — fix it and
  consider whether the helper's name can be made visible to the check.
- **`check-hidden-flex` sees classes, not ids.** It found 8 elements; the
  browser pass found 2 more on 046 styled by `#id` rules. When it reports a
  page, load that page and run
  `[...document.querySelectorAll('[hidden]')].filter(el => getComputedStyle(el).display !== 'none')`
  in the console before fixing — the one `[hidden]{display:none!important}`
  rule fixes all of them at once. `DEBUG_HIDDEN_FLEX=1` prints every toggle it
  resolved and from which line.
- **The a11y sweep is first-load only.** A modal, a second tab, a projector
  mode is not scanned. `harness.a11yScan(page, {impact})` exists for a
  per-tool suite to scan a state behind a click; nothing uses it yet.
- **ESLint's scope is the standalone files.** Inline `<script>` in the 86
  pages is not linted and would be a separate, larger project (shared page
  scope, every page's globals declared by hand). A new `_shared/` global goes
  in `eslint.config.js`'s `SITE_GLOBALS`; a page global a suite reads inside
  `page.evaluate()` goes at the top of that suite as `/* global name -- why */`.
- **The `--base` precache check needs `origin/main` fetched.** In the sandbox
  `git fetch origin main` first, then `npm run check:precache -- --base origin/main`.
